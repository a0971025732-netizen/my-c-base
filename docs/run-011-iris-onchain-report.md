## 核心發現：Iris 的成敗完全由「有沒有附地址」決定

| **純口語、未附地址** | 15 | ❌ 15/15 TIMEOUT（200s 無任何回應） | >200s | **無** |

### 1️⃣ 最該修的 bug：模糊提問時「完全靜默」，而不是反問

純口語提問（例：「这项目跑路了吗」「帮我查下这钱包 靠谱么」「持仓这么集中 正常吗」「this a bot wallet or a person」「any rug risk here or am i paranoid」「where did the money go after tornado」）送出後，**200 秒內畫面沒有任何東西出現** —— 不是錯誤訊息、不是「請提供地址」、不是 loading 失敗提示，就是空白。

真人在這裡會怎麼想？他不會知道「哦原來要貼地址」，他會以為**這個 agent 壞了**。這就像一台沒有顯示屏的 ATM：你插卡、按鍵，然後什麼都沒發生 —— 你不會去猜它想要你輸入密碼，你會轉頭走掉。

好消息是**失敗不收錢**（15 筆全部沒扣 credit），這比 Run 010 的 FlowCredit（扣費回樣板）健康得多。壞消息是 **15/19 = 79% 的真人式提問拿不到任何東西**，而免費額度是用來讓人留下的 —— 這裡是靜默流失，後台看不到任何失敗訊號。

**建議修法**（成本極低，效益極大）：缺地址時不要讓請求掛死，直接回一句反問 —— 「給我一個錢包地址或交易 hash，我幫你查」。單這一句就能把 79% 的靜默失敗轉成一次有效互動。

### 3️⃣ 次要疑點：Risk 分數疑似常數

兩個性質天差地遠的地址 —— 一個是 100% 信心的 Binance 交易所熱錢包、一個是 0% 信心的無標籤錢包 —— **風險分數都是 MEDIUM 69/100**。4 筆成功調用的風險分數全是 69。這看起來不像在評分，像是落回了預設值。建議查 risk scoring 是否實際生效。

## 對照 Run 010 的結論

| Agent | 行為 |
|---|---|
| Finance Data | ✅ 穩定出貨，承接模糊口語佳（但慢） |
| Iris | ⚠️ 有地址則優秀；無地址 100% 靜默逾時，**但不收費** |

共通模式：**agent 幾乎都假設使用者會給出結構化輸入**，而真人不會。平台層值得加一道「輸入不足時強制回一句反問」的規範，而不是任由各 agent 把請求掛死。
